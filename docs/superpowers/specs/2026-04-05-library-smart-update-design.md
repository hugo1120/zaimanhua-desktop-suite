# 书库智能更新设计

**日期：** 2026-04-05

## 背景

当前书库页有两个明显问题：

1. 书库页首屏虽然先读缓存，但挂载后会立刻触发一次 `refreshLibrary()`，导致每次进入页面都扫描机械盘目录，2000+ 漫画场景下首屏等待明显、刷新按钮长时间转圈。
2. “更新全部”会把当前书库条目整批入队；真正的去重发生在下载任务内部，先拉详情、再枚举所有章节、最后才按本地 `.cbz` 是否存在跳过。结果是不会大量重复下载，但会重复做远端详情请求和章节枚举，时间都耗在“无意义检查”上。

## 目标

- 书库页默认走缓存首屏，不在页面挂载时主动扫盘。
- 新增“智能更新”路径，只处理最近更新里确实命中本地书库、且远端更新时间晚于本地记录的作品。
- 保留一条手动“全量更新”路径，作为删过旧章节、怀疑漏内容时的补漏入口。
- 让用户能区分“缓存展示”“手动刷新校验”“智能更新”“全量补漏”这四种动作，避免状态误解。

## 非目标

- 第一阶段不引入文件系统监听。
- 第一阶段不记录每本漫画的完整章节索引。
- 第一阶段不尝试在“智能更新”里补回“远端未更新但本地被手删的旧章节”。

## 约束

- 沿用现有 React + FastAPI + 应用服务结构，不做跨层重构。
- 不移除现有 `repair_metadata()`、全量入队和下载队列逻辑，只在其外侧增加更高效的筛选链路。
- 以最小改动修正用户感知问题：启动慢、刷新转圈、更新全部太重。

## 选定方案

### 1. 书库页改为缓存优先

- 保留 `GET /api/library` 的现有行为：优先返回缓存，没有缓存时再扫盘。
- 去掉书库页挂载后的自动 `refreshLibrary()` 调用。
- 页面在 `source === "cache"` 时显示轻量提示，例如“当前显示缓存，未校验磁盘；如需同步本地文件请手动刷新”。
- “刷新”按钮仍然保留，点击时才执行目录扫描。

这样做可以直接解决启动慢和刷新按钮长时间转圈的问题，同时不破坏用户手动校验本地书库的能力。

### 2. 新增后端智能更新候选接口

- 在 `LibraryService` 中新增“智能更新候选”逻辑，并通过 `library` 路由暴露新接口。
- 该逻辑不扫描本地目录，而是直接基于当前书库缓存恢复出的条目构建 `local_by_id` 映射。
- 然后从现有漫画 API 拉取最近更新前若干页，默认扫描固定页数上限，例如 10 页。
- 对每条最近更新记录执行以下判断：
  - 该漫画 id 在本地书库中存在。
  - 远端 `last_updatetime` 大于本地 `last_update_ts`，或本地没有 `last_update_ts`。
- 命中后返回候选列表及统计信息：扫描页数、最近更新条目数、命中书库数、缺少 id 的本地条目数、最终候选数。
- 最近更新结果按漫画 id 去重，避免同一本书跨页重复入选。

### 3. 前端提供两条更新路径

- 新增 `智能更新` 按钮，调用智能更新候选接口，只把候选作品批量入队。
- 保留现有全量入队逻辑，但按钮名称改为 `全量更新`，明确它是补漏入口，不再作为默认路径。
- `智能更新` 的反馈文案要明确告诉用户：
  - 扫描了最近多少页。
  - 命中了多少本本地漫画。
  - 实际加入队列多少本。
  - 没有候选时提示“最近更新未命中本地书库或本地已是最新”。

### 4. 补漏策略

第一阶段采用“双路径”策略：

- 日常使用 `智能更新`，减少无意义扫描和无意义远端详情请求。
- 怀疑自己删过旧章节、或希望强制补漏时，手动点 `全量更新`。

这比一开始就引入章节索引更稳妥，开发量更小，也更容易验证真实收益。

## 后续可选扩展

如果第一阶段上线后，用户仍然频繁遇到“旧章节被手删但智能更新补不回”的问题，再进入第二阶段：

- 在下载完成时把章节 id 或生成出的 cbz 文件名写入 `info.json` 或单独的 `chapters_index.json`。
- 智能更新候选判断时，额外检查“索引中应存在但本地文件缺失”的章节。
- 这样即使远端近期没有更新，也能识别本地缺口并补下。

这个能力明确放到第二阶段，避免第一阶段过度设计。

## 错误处理

- 最近更新接口失败时，智能更新返回明确错误，不回退到全量更新，避免静默触发重操作。
- 本地缓存里缺少 `id` 的作品不参与智能更新，但要在统计里反馈数量，便于用户后续点“补全”。
- 智能更新候选为空时，前端不再触发任何入队请求。

## 测试策略

- 后端用 pytest 覆盖候选筛选规则：
  - 仅远端时间更新的作品会入选。
  - 缺少本地 id 的作品会被跳过并计数。
  - 最近更新跨页重复 id 只会入选一次。
- 前端用 Vitest 覆盖：
  - 书库页挂载时不再自动刷新。
  - `智能更新` 只入队候选列表中的作品。
  - `全量更新` 仍然保留现有批量入队行为。
  - 缓存提示、空候选提示、统计文案正确。

## 验收标准

- 打开书库页时，已有缓存的情况下不再触发磁盘扫描。
- “刷新”按钮仅在用户主动点击时转圈。
- `智能更新` 在 2000+ 书库场景下，只处理最近更新命中的少量作品。
- `全量更新` 仍可作为手动补漏兜底路径使用。
