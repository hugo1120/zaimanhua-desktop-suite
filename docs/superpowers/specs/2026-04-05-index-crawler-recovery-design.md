# 索引更新恢复设计

**日期：** 2026-04-05

## 背景

当前桌面版的“索引工具”已经有完整的前后端入口，但在实际更新失败时，界面只能看到任务启动和结束，无法明确知道是网络失败、线程异常，还是没有抓到新数据。

旧版单体应用 `API参考/V11.py` 的索引更新流程虽然和现有 `MangaCrawler` 核心抓取逻辑同源，但在任务外层多了一层已经验证过的控制流程：

- 启动时根据本地 `manga_list.txt` 计算最大 ID，生成默认更新范围。
- 在线程外层统一捕获异常并把错误回传到 UI。
- 结束时明确告知任务完成，而不是让状态停留在模糊的中间态。

## 目标

- 保留当前项目现有的索引抓取主逻辑和前后端接口，不回退为旧版 Tk 弹窗架构。
- 把 `V11.py` 中已验证的“索引任务外层控制”语义接回当前架构。
- 让索引更新在失败、停止、无新数据和正常结束时，都能给出明确状态。
- 最终重新打出完整的 `dist/hugo-zaimanhua/`，供用户直接覆盖现有发布目录。

## 非目标

- 不重写 `MangaCrawler` 的抓取算法、保存格式和线程池结构。
- 不改动现有 `/api/crawler/*` 接口路径和基本请求结构。
- 不引入新的索引文件格式或索引数据库。

## 约束

- 用户要求“现有逻辑不变”，因此所有改动必须限定在旧版外层流程的补回和失败可见性增强，不能把当前索引功能重构成新体系。
- 当前会话未获得显式的子代理授权，因此代码 Review 改为主 agent 的独立审查，不派生 reviewer subagent。
- 交付物必须包含完整桌面应用打包目录，而不是仅提供源码补丁。

## 方案对比

### 方案 1：最小接回旧版外层流程

- 保留现有 `zaimanhua/services/crawler.py` 里的抓取和保存逻辑。
- 在 `CrawlerService` 与设置页层面补回旧版的任务启动、异常回传、结束态处理。
- 对 `MangaCrawler` 仅做最小增强：对请求环境和异常摘要做可观测性补丁，不改变成功路径。

优点：

- 改动面最小，最符合“现有逻辑不变”。
- 与当前 React + FastAPI 架构兼容。
- 风险低，便于补测试和快速打包交付。

缺点：

- 结构上仍然沿用当前分层，不会把索引模块彻底抽象成新的任务系统。

### 方案 2：整体搬回旧版索引模块

- 直接把 `V11.py` 的索引更新模块整体搬入当前项目。

优点：

- 最接近旧版行为。

缺点：

- 会引入重复实现，且与当前前后端分层冲突。
- 维护成本高，不符合当前项目结构。

### 方案 3：新增独立索引任务包装层

- 新建一个面向桌面版的索引任务 runner，把旧版流程重新抽成新模块。

优点：

- 边界更清晰，后续扩展更方便。

缺点：

- 对当前问题来说属于过度设计，开发和回归成本偏高。

## 选定方案

采用方案 1。

## 详细设计

### 1. 后端任务外层控制补回旧版语义

在 `CrawlerService` 中保留现有线程模型，但补回旧版 `start_crawler_task()` 的关键语义：

- 后台线程统一包裹 `try/except/finally`。
- `crawler.run()` 抛出异常时，状态栏消息改成 `爬虫错误: ...`，而不是静默结束。
- 结束时确保 `running` 状态切回 `false`，并保留最后一条有意义的状态消息。

### 2. 爬虫最小可观测性增强

在 `MangaCrawler` 中只做两类最小改动：

- 会话配置与主 API 客户端保持一致，避免索引更新和其他 API 请求走不同的系统环境配置。
- 当详情请求连续失败且未抓到任何新数据时，生成可回传的错误摘要，让 UI 能区分“无新数据”和“请求整体失败”。

这些改动不改变已有抓取成功路径，也不改变 `manga_list.txt` 的格式。

### 3. 设置页补齐错误反馈

设置页继续使用现有按钮和轮询状态，但补上：

- 启动失败时的错误提示。
- 后端回传错误消息时的显式展示。

页面结构不重做，只增强用户对状态的感知。

## 测试策略

- 后端 pytest：
  - `CrawlerService` 在线程中抛错时，最终状态应保留错误消息。
  - `MangaCrawler` 会话配置与主 API 客户端一致。
  - `MangaCrawler` 在全部请求失败且没有新数据时，应给出失败摘要而不是仅输出“任务结束”。
- 前端 Vitest：
  - 设置页在 `startCrawler()` 失败时显示错误反馈。

## 验收标准

- 启动索引更新后，若后台线程异常，设置页可看到明确错误消息。
- 若索引请求因网络或环境失败而未抓到任何数据，状态不再只显示“任务结束”。
- 现有起止 ID、启动/停止按钮和实时状态区域继续可用。
- `build_exe.bat` 能重新生成完整 `dist/hugo-zaimanhua/` 目录。
